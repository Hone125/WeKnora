## 一、我们在做一件什么事

报名了腾讯犀牛鸟的 WeKnora 开源课题，选了**课题三：质量评测基线与成本可观测**，目标冲「卓越奖」。

一句话说清楚这个课题要干嘛：**给 WeKnora 这个开源知识库项目，补上一套"评测 + 算钱"的工程体系**。

- 「质量评测」：目前 WeKnora 虽然有计算指标的能力，但结果是存在内存里的，程序一重启就没了，也没法让别人复现、没法在代码改动时自动拦住"变差"的改动。
- 「成本可观测」：每次调用大模型（比如让 DeepSeek 生成答案）花了多少 token、多少钱，目前只写在日志里，没有一张表能查、能算账。

所以我们要做的，就是把这些"散的"东西，变成"工程化、可复现、可算钱"的完整体系。

## 二、之前干了什么（按时间线）

### 阶段 1：定方向、写规划（还没写代码）

1. 读了两份 PDF，确认选题是课题三。
2. 先把 WeKnora 的代码读了一遍，搞清楚它现在到底有哪些能力、缺哪些东西。
3. 输出了一份总规划，存到了 `docs/rhino-topic3-plan.md`。
4. 替用户做了两个技术决定，也写进了规划里：
   - **embedding 缓存用什么存** → 决定用「进程内缓存 + 数据库持久化」两层。
   - **费用单价从哪里来** → 决定在模型配置里加"价格字段"，而不是硬编码所有厂商的价目表。

### 阶段 2：把开发环境搭起来（P0 前半段）

1. 装了 Go（后端语言）、Docker（跑数据库等基础设施）。
2. 配置了真实的大模型（硅基流动 SiliconFlow 平台）：
   - DeepSeek-V3（负责"生成答案"）
   - bge-m3（负责"把文字转成向量"，做检索用）
   - API Key 填进了 `.env` 文件。
3. 配了两个配置文件：
   - `.env`（模型地址、密钥等）
   - `config/builtin_models.yaml`（告诉程序"默认用哪两个模型"）
4. 解决了一个编译难题：
   - 项目里的 `sqlite-vec` 组件编译时需要 `sqlite3.h` 头文件。
   - Windows 上默认没有，导致一直编译失败。
   - 解决办法：把头文件复制到项目里（新建 `third_party/sqlite/` 目录），再改一处启动脚本 `scripts/dev.sh`，让它能找到这个文件。

### 阶段 3：把"现有评测"跑通，拿到基线（P0 后半段）

1. 后端成功启动（监听在 8080 端口）。
2. 走通完整评测流程：注册账号 → 登录拿 token → 发评测请求 → 轮询结果 → 拿到指标数字。
3. 把结果写成了 `docs/rhino-topic3-baseline.md`。

## 四、下一步要干啥（M1：可复现评测）

M1 是 5 个模块里最核心的一个。目标：**让评测结果能存进数据库、能被别人用一条命令复现出来。**

按顺序做 4 件事：

**第 1 步：扩充数据集（最先做）**
- 现状：只有 1 个问题、5 段话，没法信。
- 要做：弄出几十个问题（配套答案和"标准答案段落"），存成和现在一样的 parquet 格式。
- 先读项目里生成数据的脚本 `dataset/qa_dataset.py`，搞明白格式再动手扩。

**第 2 步：把评测结果存进数据库（核心）**
- 现状：结果存在内存里，程序一重启就没了（"不可复现"的根源）。
- 要做：新建数据库表，把"每次评测的配置 + 结果"都存下来，重启也不丢。

**第 3 步：一次评测同时产出四类结果**
- 现在只有"检索准不准、答案像不像"两类。
- 要补上「花了多少钱」「花了多少时间」两类，变成四类。

**第 4 步：一条命令复现**
- 让别人拿到代码，敲一条命令，就能得到一模一样的成绩。
